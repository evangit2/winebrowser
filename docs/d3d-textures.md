# D3D8/9 2D textures

The browser JIT can create, fill, bind and sample native PE32 D3D8/9 textures.
This is a bounded fixed-function path, not general D3D8/9 compatibility.
`src/d3d9-textures.js` owns guest resources and `src/d3d-texture-renderer.js`
uploads their immutable draw snapshots to WebGPU. The D3D8 frontend preserves
its different CreateTexture argument count, texture vtable slots, descriptor
layout and sampler states embedded in Set/GetTextureStageState.

## Resources and ownership

CreateTexture accepts dimensions up to 2048×2048, explicit mip counts or zero
for the full chain, usage zero or DYNAMIC, and DEFAULT/MANAGED/SYSTEMMEM/SCRATCH
pools. DYNAMIC requires DEFAULT; only MANAGED and DEFAULT can be sampled. Non-dynamic DEFAULT locks fail. Formats are A8R8G8B8, X8R8G8B8,
R5G6B5, X1R5G5B5, A1R5G5B5, A4R4G4B4 and A8. CheckDeviceFormat reports these
2D texture formats and the supported usages; other resource queries fail.

GetLevelCount, GetLevelDesc, GetDevice, GetType, priority and managed Set/GetLOD
are implemented. Each mip uses a four-byte-aligned pitch. LockRect returns a
guest pointer at the requested subrectangle, retaining the full row pitch.
Overlapping locks on one level, invalid levels/rectangles/flags and invalid
DISCARD combinations fail without changing the output. Writable UnlockRect
invalidates the cached upload. READONLY locks leave it intact; drawing a locked
texture fails. AddDirtyRect validates the rectangle and invalidates the snapshot.
Dirty-region upload optimization and UpdateTexture are not yet implemented.

COM references keep the device alive; bindings retain backing storage separately
to avoid a device/resource reference cycle. GetTexture can restore an external
COM reference to an internally bound texture. Rebinding or device destruction
frees storage when its last owner goes away. Allocation failure rolls back memory
and device references. Released guest COM pointers remain reserved. The existing
64-total-object COM limit still applies and needs expansion for large applications.

## Sampling and queued draws

XYZ + diffuse vertices may include one float2 texture coordinate (`FVF 0x142`,
24-byte stride); the earlier 16-byte layout remains supported. Missing coordinate
sets sample (0,0). One active texture stage supports SELECTARG1, SELECTARG2,
MODULATE and ADD for color and alpha, with DIFFUSE/CURRENT/TEXTURE arguments,
COMPLEMENT and ALPHAREPLICATE. COLOROP DISABLE terminates texturing. An unbound
texture used by a color operation disables the stage, matching the fixed-function
pipeline. Other active stages fail explicitly.

Samplers support independent wrap/mirror/clamp U/V addressing, point/linear
minification and magnification, no/point/linear mip filtering, finite LOD bias
within ±16, maximum mip level, and managed resource LOD. WebGPU bias is capped
at 15.99. MIPFILTER NONE ignores MAXMIPLEVEL but honors resource LOD. Derivatives
select minification versus magnification before WebGPU's LOD clamp; this preserves
MINFILTER when shrinking textures with mipmapping disabled or only one level.
The virtual implementation does not promise a particular physical GPU's LOD
precision or filtering rounding.

Each draw copies state and references a snapshot of the texture revision it saw.
Later locks cannot alter earlier queued draws. Repeated draws of an unchanged
texture share conversion/upload data; WebGPU textures, views, samplers and bind
groups are reused. Conversion writes directly into RGBA arrays without per-texel
objects. Old GPU revisions are removed after their final submitted frame completes.

Guest texture storage is capped at 32 MiB per runtime. Frames accept up to 32 MiB
of unique expanded RGBA texture data in addition to the existing 8 MiB geometry
budget. Caps advertise one texture/stage/coordinate set, 2048×2048 NPOT mipmapped
2D textures, and only the implemented filter, addressing and operation flags.
Cube/volume/compressed textures, surface-level interfaces, render-to-texture,
autogenerated mips, projected coordinates, texture transforms, border/anisotropic/
sRGB filtering, multiple active stages and shader texture bindings remain missing.

## Evidence

- `npm run build:textures` builds the native D3D8/9 PE32 fixtures from
  `tests/fixtures/textures/main.c`; no pretranslated application Wasm is used.
- `npm run test:textures` uploads both EXEs and ZIPs through the normal UI.
  Guest code checks mip descriptors and binding lifetime, writes rows with
  rectangular locks, and draws old/new texture revisions side by side.
  Every displayed pixel is checked and all four runs exit with code zero:
  [native results](../evidence/textures-browser-results.json).
- `npm run test:textures-backend` and the same script with `--force-readback`
  check 47 cases / 192,512 pixels per mode: addressing, RGB32/RGB565 color
  operations, alpha operations in the persistent attachment, mip selection/bias,
  managed LOD, point/linear minification including single-level textures, revision
  ordering and cache cleanup. See [canvas](../evidence/d3d-textures-backend.json)
  and [readback](../evidence/d3d-textures-backend-readback.json) results.
- Unit tests cover D3D8/9 ABI differences, raw sampler queries, formats, locks,
  snapshots, cross-device rejection, reference revival, allocation rollback and
  texture budget exhaustion. Existing color/depth/shader/DX12 browser gates pass.

Original Hamsterball passes its initial D3D8 MIPMAPLODBIAS state and now stops
at the x86 repeat prefix at `0x4a6988`, after mapping `shadow.png`, after 8,884,000
guest instructions. This is the separate real-Wine loader diagnostic; no game
frame is presented yet. The normal upload fixtures establish the implemented
texture path, not independent-game compatibility or instant arbitrary startup.

Semantics were checked against the pinned Wine D3D8 headers and sampler-state
mapping in device.c/stateblock.c, plus Microsoft's
[LockRect](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3dtexture9-lockrect),
[sampler states](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dsamplerstatetype)
and [texture-stage states](https://learn.microsoft.com/en-us/windows/win32/direct3d9/d3dtexturestagestatetype).
