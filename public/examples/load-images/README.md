Authored MIT native PE32 EXE and resource DLL. Build with `npm run build:load-images`; run Chromium acceptance with `npm run test:load-images`.

The unchanged Windows SDK client exercises both six-argument LoadImage A/W interfaces, integer/named bitmap resources, normal resource icons/cursors, requested bitmap sizes, LR_CREATEDIBSECTION, system palette flags, and BMP files through the guest filesystem. Resources and files cover indexed/CORE/monochrome/RGB24/32 and RGB565 layouts. A file with an explicit gap before its pixels verifies bfOffBits handling; missing/truncated files and invalid sizes fail. Native GetObject/GetPixel and VirtualQuery check actual bitmap handles, colors, depths and writable pointers. Pixels remain valid after the resource DLL unloads.

The window displays original resource pixels, themed resource pixels, and a top-down BMP file. F6 writes through the loaded DIB's native pointer and repaints its first pixel; press again to restore it. Chromium scans all 49,152 displayed pixels in each of three stages and requires native cleanup/exit zero. The report includes input hashes, native DLL history and browser-local x86-to-Wasm translation metrics. MinGW builds native fixture inputs on the host; their unchanged machine code is translated in the browser during execution.

Bitmap sizing currently uses nearest-neighbor samples. HALFTONE filtering, compressed/embedded-image BMPs, predefined OEM bitmap assets, custom-size/file icon and cursor loading, and universal Windows compatibility remain unfinished. All image/resource data and programs are authored MIT fixtures, with no proprietary application assets.
